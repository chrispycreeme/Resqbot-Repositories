System Architecture & Overview

Technical breakdown of the ResQBot dual-microcontroller reconnaissance platform and desktop station integration.

Dual Microcontroller Architecture

ResQBot utilizes two independent ESP32 microcontrollers to segregate video capture and sensor telemetry workloads:

  • ESP32-CAM Node: Dedicated OV2640 camera streaming node posting binary JPEG frames over HTTP POST to the central server.
  • ESP32-Main Station Node: Core processing node parsing MLX90640 thermal UART telemetry, driving the SSD1306 OLED, executing L9110 motor PWM ramping, and controlling the alarm buzzer.

Python Control Station & AI Pipeline

The central Flask and Tkinter application hosted on the PC processes raw stream feeds in real time:

  • YOLO Person Detection: Evaluates incoming JPEG frames using the person.pt neural network model.
  • Thermal JET Interpolation: Converts 768 floating-point temperature values into a 24x32 color-mapped thermal matrix.
  • WASD Steering Engine: Translates operator key controls into differential motor PWM speed targets.
SAFETY PROTOCOL SUMMARY
Always ensure the main Rocker Switch is set to Position O (Charge Mode) before plugging in USB Type-C charging power. Operating or charging with reversed polarity will result in permanent hardware damage.

Step-by-Step Commissioning & Boot Guide

Sequential operations workflow to safely verify hardware wiring, initialize host software, provision microcontrollers, and operate the robot.

01
Physical Wiring & Electrical Calibration
Before applying main battery power, verify all electrical connections and rail voltages using a digital multimeter.
  • Confirm 3S battery leads are wired to the 3S charger module: BAT+ (Red) and BAT- (Black).
  • Verify the LM2596 buck converter input terminals connect to the switched output of the Rocker Switch.
  • Voltage Calibration: Disconnect microcontrollers from the 5V rail. Toggle Rocker Switch to Position I and measure LM2596 output with a multimeter. Adjust brass potentiometer until output reads exactly 5.00V DC.
  • Ensure a shared common ground bus links all GND pins across ESP32-Main, ESP32-CAM, OLED, MLX sensor, Ultrasonic sensor, Buzzer, and L9110 motor driver.
02
Python Environment Setup & Model Deployment
Install required Python 3.10+ dependencies and verify neural network weight files.

Run package installation in terminal:

pip install ultralytics opencv-python pillow flask requests numpy

Confirm that the YOLO neural network model file person.pt is located inside the python/ folder.

03
Host Server Launch & Local IP Identification
Execute the central desktop control station and record the host IP address.

Start the application server:

python python/app.py

Observe the window header displaying the host address: Server Running @ http://<HOST_IP>:5000 (e.g. http://192.168.18.155:5000). Note this IP address for provisioning steps.

04
System Power On & Microcontroller AP Provisioning
Provision WiFi credentials and server target IP into NVS flash memory on both microcontrollers.
  1. Toggle main Rocker Switch to Position I (System Power ON).
  2. ESP32-CAM Provisioning: Connect PC/mobile to WiFi AP ResQBot-CAM-AP. Navigate browser to http://192.168.4.1. Input local WiFi SSID, Password, and Server IP. Click Connect & Continue Operations.
  3. ESP32-Main Provisioning: Connect PC/mobile to WiFi AP ResQBot-Main-AP. Navigate browser to http://192.168.4.1. Input identical local WiFi SSID, Password, and Server IP. Click Connect & Continue Operations.
05
Telemetry Verification & Steering Operations
Verify active stream feeds and test differential motor steering controls.
  • Inspect SSD1306 OLED display on robot: verify WiFi: Connected, Python App: Connected, and MLX: OK.
  • Inspect Python Desktop App GUI: verify live camera feed with YOLO bounding boxes and thermal JET heat map display.
  • Click inside Tkinter window and test WASD steering: W (Forward), S (Reverse), A (Spin Left), D (Spin Right), Spacebar (Emergency Stop).
06
Shutdown & 3S Type-C Charging Protocol
Safely isolate electronics and execute battery charging procedure.
  1. Press Spacebar in app window to stop motor outputs.
  2. Toggle Rocker Switch to Position O (Charge Mode) to disconnect system electronics.
  3. Plug USB Type-C charging cable into 3S charger module port.
  4. Verify Red LED is lit during charging. Disconnect charger once Blue LED indicates full charge.

Diagnostic & Troubleshooting Matrix

Search or filter resolution protocols for power, connectivity, sensor, and motor failure modes.

Scenario 1: Robot does not turn on or shuts down under motor load Power System
Possible Cause: Switch set to Charge Mode, low battery voltage, or LM2596 loose wire connection.
Action:
  1. Verify Rocker Switch is toggled to Position I (System Power ON).
  2. Measure battery voltage with multimeter across BAT+ and BAT- (must be >10.5V DC).
  3. Inspect LM2596 screw terminals and verify OUT+ output reads 5.00V DC.
Scenario 2: Battery fails to charge when Type-C cable is connected Charging
Possible Cause: Switch left in Position I, faulty USB cable, or battery terminal disconnected.
Action:
  1. Switch MUST be set to Position O (Charge Mode) during charging.
  2. Verify the Red LED on 3S charger module illuminates. If no LED lights, test with another Type-C cable and 5V/2A power adapter.
  3. A Blue LED indicates battery is already fully charged.
Scenario 3: ESP32-CAM video stream offline or missing in Python app Camera
Possible Cause: Server IP address mismatch, Windows Firewall blocking port 5000, or insufficient 5V supply current.
Action:
  1. Connect smartphone to ResQBot-CAM-AP, navigate to 192.168.4.1, and verify your Host PC IP address.
  2. Allow Python through firewall for Port 5000.
  3. Ensure ESP32-CAM receives steady 5V power supply from regulator output rail.
Scenario 4: OLED shows "MLX: NO" or thermal heatmap is frozen Thermal Sensor
Possible Cause: Loose UART wires (RX2/TX2), swapped RX/TX lines, or missing 1.5s boot delay.
Action:
  1. Confirm MLX90640 TX is wired to ESP32 GPIO 16 (RX2), and MLX RX to GPIO 17 (TX2).
  2. Ensure sensor receives stable power. Wait 5 seconds for auto-healing loop to re-initialize UART connection.
Scenario 5: Motors spin in reverse direction or ignore WASD controls Motor Driver
Possible Cause: Reversed motor terminal leads or lost window focus in Python app window.
Action:
  1. If Motor A spins backward when pressing W, swap the two output wires connected to MOTOR A screw terminal on L9110 driver.
  2. Click inside Tkinter desktop window to ensure keyboard focus for WASD steering.
Scenario 6: SSD1306 OLED display remains completely dark on boot Display
Possible Cause: Swapped SDA/SCL pins, wrong I2C address, or loose power connection.
Action:
  1. Verify OLED SDA connects to GPIO 21 and SCL to GPIO 22.
  2. Check that VDD receives 5V (or 3.3V) and GND is securely connected. ESP32-Main code automatically scans I2C addresses 0x3C and 0x3D.
Scenario 7: Alarm buzzer does not sound when person is detected Buzzer
Possible Cause: Loose GPIO 27 connection, passive buzzer used instead of active buzzer, or missing person.pt model file.
Action:
  1. Ensure an Active 5V Piezo Buzzer is wired to GPIO 27.
  2. Confirm person.pt model file exists in python/ directory.
  3. Test buzzer manually by accessing http://<ESP32_IP>/beep in web browser.
